# Evidence methodology

RoleProof's visuals are executable evidence, not hand-authored product mockups.
The committed bundle is generated from the same synthetic policy, analysis
receipt, verification, and static site that the CLI and tests use.

## Inventory

| File | Provenance |
|---|---|
| `roleproof-dashboard.png` | Real 1440 × 1000 Chromium viewport |
| `roleproof-full-page.png` | Full real dashboard page |
| `roleproof-mobile.png` | Real 390 × 844 mobile viewport |
| `roleproof-interaction.gif` | Four real constraint-selection states |
| `roleproof-cli.png` | Browser rendering of captured CLI stdout |
| `roleproof-cli.txt` | Exact CLI stdout |
| `roleproof-role-graph.svg` | Graph rendered from normalized policy and receipt |

| `roleproof-analysis.json` | Actual analysis receipt |
| `roleproof-verification.json` | Actual independent verification |
| `roleproof-evidence.json` | Source, runtime, file-size, and SHA-256 manifest |

No file outside this exact inventory is accepted under `docs/evidence/`.

## Capture pipeline

1. Check out the exact PR or main revision with no persisted credentials.
2. Derive the latest revision that changed policy, runtime, frontend, or capture
   sources, then record that commit and its tree.
3. Compile the Python evidence generator.
4. Install the empty Node dependency graph, run the test suite, and build the
   nine-file static site.
5. Execute the real CLI audit in an isolated temporary directory and compare its
   four output files with the site build's receipt data.
6. Download exactly five hash-locked CPython wheels.
7. Pull the Playwright image by the linux/amd64 platform-manifest digest.
8. Run capture with no network, no capabilities, a read-only source mount, and
   bounded resources.
9. Verify inventory, symlinks, dimensions, GIF frame count, SVG safety, secret
   patterns, receipt binding, source records, and every file hash.
10. Compare every generated byte with the committed bundle.

The adoption workflow ran this process twice and accepted evidence only when
both candidate trees were byte-identical. That write-capable workflow was then
removed. `roleproof-evidence.yml` is permanently read-only.

## Runtime lock

The manifest records:

- Chromium 151.0.7922.34;
- Playwright 1.62.0;
- Pillow 12.3.0;
- CPython 3.12-compatible hash-locked wheels; and
- `mcr.microsoft.com/playwright/python` at platform manifest
  `sha256:51d31fdfacb0cff99a1a724152e34ae408d2bd4e7da310ff157450f49261cc59`.

The image's architecture and OS are checked as `amd64/linux` before capture.

## Reproducing locally or in CI

The permanent workflow
[`.github/workflows/roleproof-evidence.yml`](../.github/workflows/roleproof-evidence.yml)
is the canonical executable recipe. It intentionally writes only beneath the
runner's temporary directory and compares the result with the repository.

For ordinary development, run the fast contract first:

```bash
npm ci --ignore-scripts
npm run check
npm run build
node src/cli.mjs audit examples/orion.synthetic.json --out roleproof-audit
```

If a policy, runtime, frontend, build, browser lock, or capture source changes,
the visual workflow should fail until the complete evidence bundle is
regenerated and reviewed. Documentation-only changes do not falsify the
recorded source revision.

## Claim boundary

The fixture is synthetic. The captures contain no live IAM connection,
employee data, provider attestation, benchmark result, credential, personal
path, or hidden API response. Image labels that describe results are populated
from the verified receipt, and the manifest makes those inputs inspectable.
